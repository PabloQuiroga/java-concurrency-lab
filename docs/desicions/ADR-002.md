# ADR 002: Uso de `ConcurrentHashMap` para el Estado de Activos

## Estado
Aceptado

## Contexto
El motor de decisiones necesita acceder al último precio conocido de diversos activos mientras los hilos de ingesta actualizan esos mismos precios constantemente.

## Decisión
Se utilizará `ConcurrentHashMap` para almacenar el mapeo de `Activo -> Precio`.

## Justificación
- **Granularidad de Bloqueo**: A diferencia de `Collections.synchronizedMap`, que bloquea toda la tabla, `ConcurrentHashMap` bloquea solo segmentos (buckets), permitiendo múltiples lecturas y escrituras simultáneas.
- **Rendimiento**: Minimiza la contención entre hilos, permitiendo que el motor de decisiones lea el precio de un activo mientras otro hilo actualiza uno diferente.

## Consecuencias
- El uso de memoria es ligeramente superior a un `HashMap` convencional, pero el beneficio en la concurrencia es crítico para un sistema de alta frecuencia.
